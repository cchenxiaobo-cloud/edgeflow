# EdgeFlow 灾备能力评估报告（GB/T 20988-2025 对标）

> 版本：v0.51.0 ｜ 日期：2026-10-21 ｜ 依据：GB/T 20988-2025《信息安全技术 信息系统灾难恢复规范》
> 承接：replan §2「灾备分级（GB/T 20988-2025，RTO/RPO 六级，区域汇聚节点建议五级及以上）」+
> §5 边界表「灾备分级设计：评估承接 v0.51 评估 + v0.52 验收」。**本报告为评估文档，不改代码。**

## 1. 现状架构与恢复能力盘点

| 组件 | 现状 | 故障场景 | 恢复机制 | 现估 RTO | 现估 RPO |
|---|---|---|---|---|---|
| cloudcore（中心） | 单实例部署（嵌入式 etcd 或外部 etcd 单节点） | 进程崩溃 / 主机故障 | K8s/进程守护重启；嵌入式 etcd 数据目录持久化（PV） | 分钟级（人工或自愈重启） | ≈0（注册/规则/告警等写路径经 etcd 持久化） |
| 治理面 store（区域/标签/策略等，v0.49-0.51 新增面） | 内存 + JSON 全量快照（temp+rename 原子写，变更即落盘；env 可选路径，空=纯内存易失） | 进程崩溃 | 重启 Load 快照（孤儿清理/父链断链容错） | 同上（随 cloudcore） | ≈0（配置快照同步写；**未配 env 则 RPO=全量丢失**，部署须显式配置） |
| 边侧（edgecore） | 本地缓存 + 断网补传队列（闭环 E2） | 断网 / 边侧重启 | 本地持久化 + 恢复补传（乱序/重复幂等，v0.39 验收） | 秒级自愈 | 0（断网 30min 数据零丢失，v0.39/仿真验证） |
| 视频面 | 帧源注册表进程内存态 | cloudcore 重启 | 帧源重注册（边侧重连） | 秒级 | 会话级（可重连，无持久需求） |
| 时序数据（v0.38） | 边侧轻量时序库（断电恢复验收过） | 边侧断电 | WAL/快照恢复 | 秒级 | ≈0 |

**关键结论**：当前为**单实例 + 边侧自治**形态。边侧韧性（补传/自治）已达到较高水平；
云端为单点，RTO 依赖重启自愈，RPO 依赖各 store 持久化配置是否显式启用。

## 2. GB/T 20988-2025 六级对标

| 等级 | RTO / RPO 要求（规范口径） | EdgeFlow 现状判定 |
|---|---|---|
| 第 1 级 基本自主恢复 | RTO ≥ 2 天；RPO ≥ 24h | **已超越**（重启自愈分钟级；配置 RPO≈0） |
| 第 2 级 备场支援 | RTO ≥ 24h；RPO ≥ 4h | **满足**（前提：全部 store 快照 env 显式配置 + K8s liveness 自愈） |
| 第 3 级 具备部分恢复 | RTO ≥ 12h；RPO ≥ 30min | **部分满足**：单实例可达成；缺冷备演练与恢复预案文档化流程 |
| 第 4 级 定时数据完整 | RTO ≥ 4h；RPO < 30min | **不满足**：无第二站点/无备份数据副本管理流程 |
| 第 5 级 实时数据完整 | RTO ≥ 30min；RPO < 10min | **不满足**：需热备/多实例数据实时复制（区域汇聚节点建议等级） |
| 第 6 级 零损恢复 | RTO ≤ 30min；RPO = 0（任意点） | **不满足**：需双活集群 + 零丢失复制，超出当前架构定位 |

**现状综合判定**：配置齐备（全部持久化 env 显式配置 + K8s 自愈）下可支撑**第 2 级，
冲击第 3 级**；区域汇聚节点五级要求（replan §2）存在**结构性差距**——单实例架构
无法通过补丁达到，需 G01 候选路径 1（分区多实例联邦）或路径 2（轻量区域管理节点）
立项实施。

## 3. 差距清单（现状 → 五级路径）

| # | 差距 | 影响 | 处置路径 | 承接 |
|---|---|---|---|---|
| 1 | cloudcore 单实例，无热备 | 中心故障 RTO 分钟级+，不可满足 5 级 RTO≥30min | K8s liveness+PV（→2 级）；外部 etcd 3 节点集群（→3 级）；多实例联邦/区域管理节点（→5 级） | v0.52 验收 2-3 级落地项；5 级立项评估（replan §3.5） |
| 2 | 嵌入式 etcd 单点（默认部署形态） | 数据面单点；无跨节点复制 | 部署侧切换外部 etcd 集群（架构已支持，v0.46 起装配分叉） | v0.52 部署基线 |
| 3 | 治理面 JSON 快照依赖显式 env | 漏配则 RPO=全量丢失 | 部署基线强制配置项（基线清单登记）；etcd 写穿化评估 | v0.52 分级配置基线（G33） |
| 4 | 无灾备演练流程/预案文档 | 3 级要求的「恢复预案」缺口 | 演练脚本 + 预案模板（恢复步骤/SOP） | v0.52 验收报告组成部分 |
| 5 | 备份副本管理（备份周期/异地保存）缺失 | 4 级门槛 | 备份策略入基线（etcd snapshot 定时 + 快照文件异地同步） | v0.52 验收 |
| 6 | 边侧自治已达标但未做长时间实测 | RPO=0 结论基于仿真 | 30min+ 真实长跑 | v0.52（G30 规模验收） |

## 4. 处置建议与版本承接

- **v0.52（规模、信创与基线）承接**：差距 #1 前两级（K8s 自愈基线 + 外部 etcd
  部署基线）、#3（持久化 env 入分级配置基线，强制项）、#4（恢复预案 SOP + 演练
  脚本）、#5（备份策略基线）、#6（30min+ 长跑实测 RPO 验证）。验收形态：三类报告
  （含本报告差距项的落地核验）。
- **5 级立项评估（v0.52 后专项）**：前提是 v0.52 100 节点规模数据支撑路径裁决
  （分区多实例联邦 vs 轻量区域管理节点）；跨实例数据复制（etcd 集群/双活网关）
  与区域汇聚层职责划分是核心设计题，不在本版承诺范围。
- **诚实性声明**：本报告判定基于代码事实与 e2e/单测验证过的行为；「≈0 RPO」
  均以「持久化配置显式启用」为前提；未实测项（长跑/演练）如实登记为差距，
  不以仿真结论替代。

## 5. 结论

EdgeFlow 当前灾备能力达到 **GB/T 20988-2025 第 2 级（配置齐备前提），冲击第 3 级**
；与 replan 建议的区域汇聚节点五级要求存在结构性差距，差距项全部登记并有明确
版本承接（v0.52 承接 2-3 级落地项；5 级待规模数据后专项立项）。本结论与
replan §5 边界表「评估承接 v0.51 评估 + v0.52 验收」一致。
