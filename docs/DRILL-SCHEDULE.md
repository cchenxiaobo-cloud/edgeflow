## 2. 演练范围（Scope）

> 演练步骤参照 `docs/UPGRADE.md` §5 端到端演练（已在离线产物环境实测 6/6 通过），
> 本次为**真实集群 + 真实节点**版本。

### 2.1 场景链（升级 → 人为故障 → 回滚 → 数据校验）

| # | 场景 | 操作 | 预期结果 | 判定标准 |
|---|------|------|----------|----------|
| 1 | 基线快照 | 记录产物/数据 hash 基线（UPGRADE.md §5 方法）+ `keadm ops-ledger` 快照 | 基线文件生成 | 基线文件存在且完整 |
| 2 | 升级（产物） | `keadm upgrade --version=<目标版本>`（先 `--simulate-failure` 演练一次） | 版本标记更新、备份生成、台账 ok | 备份目录 + 台账 2 条记录（failed/ok） |
| 3 | 升级（真实部署） | 替换 edgecore 二进制 / 镜像 tag（helm 或节点侧），见 DEPLOYMENT.md §5.2 | 节点重连注册、Pod 由新版本接管 | `--version` 输出新版本；`/api/v1/nodes` Ready |
| 4 | 人为故障 A | `kill -STOP <edgecore pid>`（冻结心跳） | NodeController 超时扫描 → 节点 Offline（interval 默认可配） | 状态机 Offline，超时窗口内触发（NODECONTROLLER.md） |
| 5 | 人为故障 B | `kill -CONT` 恢复；或 `docker stop` 边缘 Pod 容器 | 节点恢复 Ready；Edged 健康自愈自动重启容器 | Ready 恢复；容器 12s 内重启（M3 三期实测指标） |
| 6 | 数据校验 | 升级前后 SQLite/用户文件 hash 比对 + 设备/Pod 数据抽查 | hash 一致、数据完整 | 比对通过（UPGRADE.md §5 基线法） |
| 7 | 回滚（产物） | `keadm rollback --latest` | 版本恢复、三个产物与备份 diff 一致、台账 ok | diff 无差异 + 台账记录 |
| 8 | 回滚（镜像，可选） | 按 MULTIARCH.md §6 指回旧 digest | 服务可用性恢复 | 冒烟 `/healthz` 200 |
| 9 | 清理 | 恢复正式版本（如需）+ 记录台账 + 更新发布台账 | 现场干净 | ops-ledger 全链路可查 |

### 2.2 演练判定总则

- 任何一步未达预期 → **立即停止后续步骤**，按 §5 回滚预案处置，并在发布台账 §5 登记异常；
- 演练期间业务流量按 §6 通知模板提前告知（低峰窗口 + 可接受影响声明）；
- 演练完成后 24h 内输出演练报告（结果表 + 偏差 + 改进项）。

- [ ] **审批完成**：生产变更审批（含演练窗口、影响范围、回滚负责人）签字确认；

- [ ] **回滚预案在手**：UPGRADE.md §3 异常路径表 + MULTIARCH.md §6 打印/离线可用；
- [ ] **环境校验**：`keadm ops-ledger` 可查、`/api/v1/healthz` 正常、演练对象节点无在途业务变更。

## 5. 回滚预案（Rollback Plan）

> 演练中任一步骤失败，按以下优先级止血；原则：**先恢复可用，再排查根因**。

| 优先级 | 动作 | 命令/位置 |
|--------|------|-----------|
| P0 | 恢复产物 | `keadm rollback --latest --output-dir=./keadm-out`（失败见 UPGRADE.md §3 人工 cp 路径） |
| P0 | 恢复服务 | `helm rollback edgeflow <REVISION>`（云端）；重启旧版 edgecore 二进制（节点侧） |
| P1 | 镜像回退 | MULTIARCH.md §6：单架构重建覆盖 tag 或 `docker buildx imagetools create -t <img>:v0.1.0 <img>@sha256:<旧 digest>` |
| P1 | 数据核对 | UPGRADE.md §5：hash 基线比对；异常时用 `.bak` 恢复并人工校验 |
| P2 | 演练中止 | 中止后续场景，值班通报，24h 内出复盘报告 |
