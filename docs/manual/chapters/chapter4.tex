\chapter{云端操作指南}
\label{ch:4}

本章内容：介绍 cloudcore 对外提供的全部 REST API 端点——用途、请求示例与响应字段说明，以及监控指标（\texttt{/metrics}）、OCSP 在线吊销查询（\texttt{/ocsp}）与 API 认证的启用方法。v0.7.0 起总端点数为 31（14 个既有端点 + 17 个模型 API 端点，详见 \S\ref{sec:endpoint-overview} 与 \S\ref{sec:model-api}）。操作人员可通过 curl 或任意 HTTP 客户端调用。

\section{通用约定}

\begin{itemize}
  \item \textbf{Base URL}：\texttt{http://<cloudcore-ip>:8080}（端口可用 \texttt{--port} 或环境变量 \texttt{EDGEFLOW\_CLOUDCORE\_PORT} 覆盖）；
  \item \textbf{数据格式}：JSON；请求需携带 \texttt{Content-Type: application/json}，响应同样为 JSON；
  \item \textbf{时间戳}：Unix 毫秒（注册、心跳、上报时间等）；
  \item \textbf{List 风格}：\texttt{edgenodes}、\texttt{pods}、\texttt{devices} 端点采用 Kubernetes List 风格（\texttt{kind}/\texttt{apiVersion}/\texttt{items}），空数据编码为 \texttt{[]} 而非 \texttt{null}；\texttt{/api/v1/nodes} 为裸数组；
  \item \textbf{路径参数}：\texttt{\{nodeID\}} 为边缘节点 ID（edgecore 注册时上报，默认 \texttt{edge-<主机名>}），必须与注册时的 nodeID 完全一致；nodeID 须匹配 \verb|^[A-Za-z0-9._-]+$|（v0.4.0 起，含 \texttt{/} 的 nodeID 拒绝写入）；
  \item \textbf{状态语义（分级持久化，v0.4.0 起）}：云端三块存储（registry/podstatus/devicestatus）由纯内存改为写穿（write-through）持久化——节点注册台账与设备 Desired 跨重启保留；心跳、Status、Pod 状态、设备上报属性与 Offline 标记不落盘，重启后短暂清空（$\leq$1 上报周期自愈，非永久丢失）；边缘侧元数据由 SQLite 持久化，不受影响；
  \item \textbf{并发语义（v0.6.0 多副本）}：外部 etcd 多副本形态下，设备 Desired 写入为 CAS（Compare-And-Swap：先读基准 revision，无变化才写入）；并发冲突重试耗尽时 HTTP 仍返回 200，仅日志输出 \texttt{concurrent-write}——属正常语义而非错误，重发指令即可收敛；
  \item \textbf{OpenAPI 契约}：OpenAPI v3 契约见 \texttt{docs/openapi/edgeflow-openapi.yaml}（由 \texttt{hack/gen-openapi.sh} 重新生成，请勿手工编辑）；API 兼容性契约测试见 \texttt{tests/contract}（v0.7.0 起覆盖全部 31 个端点，含 17 个模型 API 端点）。
\end{itemize}

完整端点总览见下一节。

\section{健康检查}

\subsection{GET /healthz}

用途：服务探活，返回云端运行状态与版本信息（Helm 部署的存活/就绪探针均指向此路径）。

\begin{lstlisting}
curl http://127.0.0.1:8080/healthz
\end{lstlisting}

响应示例（HTTP 200）：

\begin{lstlisting}
{"status":"ok","version":{"version":"v0.7.0","gitCommit":"c7aeec1","buildTime":"2026-08-25T18:00:00+0800","goVersion":"go1.26.2"}}
\end{lstlisting}

多副本语义（v0.6.0）：外部 etcd 模式且 \texttt{EDGEFLOW\_CLOUDCORE\_MULTI\_REPLICA=1} 时，\texttt{/healthz} 反映 etcd 连接状态——etcd 失联超过节点租约 TTL（\texttt{EDGEFLOW\_CLOUDCORE\_NODE\_LEASE\_TTL}，默认 300s）返回 503，K8s liveness 探针据此重启副本自愈；其余形态（纯内存、embed、单副本外部模式）恒返回 200（进程存活语义，不反映存储状态）。

\section{节点 API}

\subsection{GET /api/v1/nodes —— 全部节点（运行视角）}

用途：获取全部已注册节点，直接返回节点元数据数组（按 nodeID 排序），用于快速了解节点在线状态与平台信息。

\begin{lstlisting}
curl http://127.0.0.1:8080/api/v1/nodes
\end{lstlisting}

响应示例（HTTP 200，无节点时返回 \texttt{[]}）：

\begin{lstlisting}
[
  {
    "nodeID": "edge-node-1",
    "nodeName": "edge-node-1",
    "arch": "arm64",
    "os": "darwin",
    "edgecoreVersion": "version=v0.7.0 gitCommit=c7aeec1 goVersion=go1.26.2",
    "cpu": 8,
    "memory": 0,
    "ip": "127.0.0.1",
    "registeredAt": 1786705914423,
    "lastHeartbeatAt": 1786705914423,
    "status": "Ready"
  }
]
\end{lstlisting}

字段说明：

\begin{tabularx}{\textwidth}{l l X}
  \toprule
  \textbf{字段} & \textbf{类型} & \textbf{说明} \\
  \midrule
  \texttt{nodeID} & string & 节点唯一 ID（edgecore 的 \texttt{EDGEFLOW\_EDGECORE\_NODE\_ID}） \\
  \texttt{nodeName} & string & 云端分配的节点名（当前与 nodeID 一致） \\
  \texttt{arch} / \texttt{os} & string & edgecore 所在平台（注册时上报） \\
  \texttt{edgecoreVersion} & string & edgecore 版本串 \\
  \texttt{cpu} / \texttt{memory} & int / uint64 & 节点资源（内存：Linux 上报实际值，非 Linux 平台为 0） \\
  \texttt{ip} & string & 连接来源 IP \\
  \texttt{registeredAt} / \texttt{lastHeartbeatAt} & int64 & 注册时间 / 最近心跳时间（Unix 毫秒） \\
  \texttt{status} & string & \texttt{Ready} / \texttt{Unknown} / \texttt{Offline} \\
  \bottomrule
\end{tabularx}

\subsection{GET /api/v1/nodes/\{nodeID\} —— 单节点详情}

用途：查询指定节点。节点不存在时返回 404 与 \texttt{\{"error":"node not found",...\}}。

\begin{lstlisting}

\end{lstlisting}

\subsection{GET /api/v1/edgenodes —— 全部节点（CRD 视角）}

用途：以 EdgeNode 对象（\texttt{apiVersion: edgeflow.io/v1alpha1}）形式获取节点，Kubernetes List 风格，便于按 CRD 对象消费。

\begin{lstlisting}
curl http://127.0.0.1:8080/api/v1/edgenodes
\end{lstlisting}

响应示例（HTTP 200）：

\begin{lstlisting}
{
  "kind": "EdgeNodeList",
  "apiVersion": "edgeflow.io/v1alpha1",
  "items": [
    {
      "apiVersion": "edgeflow.io/v1alpha1",
      "kind": "EdgeNode",
      "metadata": {"name": "edge-node-1", "uid": "...", "creationTimestamp": "2026-08-14T19:11:54+08:00"},
      "spec": {"nodeID": "edge-node-1", "role": "edge"},
      "status": {"phase": "Running", "heartbeatTime": "...", "conditions": [{"type": "Ready", "status": "True"}]}

  ]
}

关键字段：\texttt{spec.nodeID}（节点唯一标识）、\texttt{spec.role}（角色，默认 \texttt{edge}）、\texttt{status.phase}（\texttt{Pending}/\texttt{Running}/\texttt{Offline}/\texttt{Unknown}）、\texttt{status.conditions}（健康条件，如 \texttt{Ready}）。

\begin{lstlisting}
curl http://127.0.0.1:8080/api/v1/edgenodes/edge-node-1
\end{lstlisting}

\subsection{GET /api/v1/devices —— 全部设备状态}

用途：获取全部设备的数字孪生状态：\texttt{properties} 为设备实际上报值，\texttt{desired} 为云端下发的期望值（设备上报不会覆盖 desired）。

\begin{lstlisting}
curl http://127.0.0.1:8080/api/v1/devices
\end{lstlisting}

响应示例（HTTP 200，内置模拟传感器 \texttt{sensor-01}）：

\begin{lstlisting}
{
  "kind": "DeviceStatusList",
  "apiVersion": "v1",
  "items": [
    {
      "nodeID": "edge-node-1",
      "deviceName": "sensor-01",
      "namespace": "default",
      "properties": {"humidity": 46.39, "temperature": 29.38},
      "desired": {"targetTemp": 25},
      "lastReportedAt": 1786705917423
    }

\end{lstlisting}

字段说明：\texttt{properties} / \texttt{desired} 均为 \texttt{map[string]float64}；\texttt{lastReportedAt} 为最近上报时间（Unix 毫秒）。

\subsection{GET /api/v1/nodes/\{nodeID\}/devices —— 单节点设备状态}

用途：查询指定节点的设备状态。语义与单节点 Pod 查询一致：节点不存在返回 404；存在但无设备返回 200 与空 \texttt{items}。

\begin{lstlisting}
curl http://127.0.0.1:8080/api/v1/nodes/edge-node-1/devices
\end{lstlisting}

\section{下发类 API（可靠下发）}

三个下发端点共用同一套可靠投递语义：消息进入 CloudHub 发送缓冲，由边缘 EdgeHub 接收并处理，处理完成后回确认（Ack）给云端，云端收到确认后返回 200；未确认时按 5 秒超时重试，最多尝试 3 次。

\subsection{POST /api/v1/nodes/\{nodeID\}/podsync —— 下发 Pod 配置}

用途：向边缘节点下发 Pod 期望配置（新增/更新/删除），由边缘 Edged 调谐容器。

\begin{lstlisting}
curl -X POST http://127.0.0.1:8080/api/v1/nodes/edge-node-1/podsync \
  -H 'Content-Type: application/json' \
  -d '{"operation":"add","pod":{"name":"nginx","namespace":"default","image":"nginx:1.25-alpine","replicas":1,"resources":{"cpuRequest":"100m","cpuLimit":"250m","memoryRequest":"64Mi","memoryLimit":"128Mi"}}}'
\end{lstlisting}

请求体字段：

\begin{tabularx}{\textwidth}{l l l X}
  \toprule
  \textbf{字段} & \textbf{类型} & \textbf{必填} & \textbf{说明} \\
  \midrule
  \texttt{operation} & string & 是 & \texttt{add} / \texttt{update} / \texttt{delete}（白名单校验） \\
  \texttt{pod.name} & string & 是 & Pod 名称（delete 时作为删除键之一） \\
  \texttt{pod.namespace} & string & 否 & 命名空间（缺省 \texttt{default}） \\
  \texttt{pod.image} & string & add/update 必填 & 容器镜像（delete 不需要） \\
  \texttt{pod.replicas} & int & 否 & 副本数（Edged 按此保证多副本） \\
  \texttt{pod.resources.cpuRequest} & string & 否 & CPU 请求量（K8s 风格，如 \texttt{100m}；零值/缺省 = 不限制） \\
  \texttt{pod.resources.cpuLimit} & string & 否 & CPU 上限（如 \texttt{250m}；零值/缺省 = 不限制） \\
  \texttt{pod.resources.memoryRequest} & string & 否 & 内存请求量（如 \texttt{64Mi}；零值/缺省 = 不限制） \\
  \texttt{pod.resources.memoryLimit} & string & 否 & 内存上限（如 \texttt{128Mi}；零值/缺省 = 不限制） \\
  \bottomrule
\end{tabularx}

响应示例（HTTP 200，边缘已确认）：

\begin{lstlisting}
{"status":"ok","acked":true}
\end{lstlisting}

操作说明：边缘收到后，容器按 \texttt{edgeflow-<命名空间>-<名称>-<序号>} 命名并打标签；\texttt{delete} 时按命名空间与名称删除元数据，Edged 回收对应容器。

\subsubsection{资源语义（v0.2.0）}

\texttt{pod.resources} 四个字段为 v0.2.0 新增（云边契约只增不改，\texttt{omitempty}；旧版边缘未配置资源时行为不变）：

\begin{itemize}
  \item \textbf{云端前置校验}：数值格式非法（含 NaN/Inf/溢出/前导 \texttt{+}）或 request $>$ limit $\rightarrow$ 400，文案含超标字段（如 \texttt{CPU request (500m) 不能超过 CPU limit (250m)}）；
  \item \textbf{超卖准入}：节点已部署 request 求和 + 新请求超出节点容量 $\times$ 超卖率 $\rightarrow$ 409 \texttt{EDGEFLOW\_RESOURCE\_EXHAUSTED}（云端拒绝，不落盘、不建容器；重试无意义，见下文八态响应语义）；
  \item \textbf{边缘准入}：admitPodResources fail-closed——边缘侧同样校验，不满足时以 error Ack 返回 502；
  \item \textbf{容器落地}：Docker \texttt{--cpus} / \texttt{--memory}（\texttt{--memory-swap} 禁用，即内存不可换出）；
  \item \textbf{资源漂移检测}：外部通过 \texttt{docker update} 等修改容器资源限制 → Edged 检测到与声明不符后自动 stop + 重建容器（镜像漂移同理），每轮最多重建 1 个（滚动门控）；漂移重建不计入 RestartCount；
  \item \textbf{节点容量}：默认自动探测，可用环境变量覆盖（见下表）。
\end{itemize}

资源调度环境变量（v0.2.0，edgecore 侧）：

\begin{tabularx}{\textwidth}{l l X}
  \toprule
  \textbf{环境变量} & \textbf{默认} & \textbf{说明} \\
  \midrule
  \texttt{EDGEFLOW\_EDGECORE\_NODE\_CPU\_MILLI} & 自动探测值 & 节点 CPU 容量（毫核）；显式设置覆盖探测值 \\
  \texttt{EDGEFLOW\_EDGECORE\_NODE\_MEMORY\_BYTES} & 自动探测值 & 节点内存容量（字节）；显式设置覆盖探测值（仅 Linux 可探测） \\
  \texttt{EDGEFLOW\_EDGECORE\_OVERCOMMIT\_CPU\_RATE} & 1.5 & CPU 超卖率：准入容量 = 节点容量 $\times$ 超卖率 \\
  \texttt{EDGEFLOW\_EDGECORE\_OVERCOMMIT\_MEMORY\_RATE} & 1.5 & 内存超卖率：准入容量 = 节点容量 $\times$ 超卖率 \\
  \bottomrule
\end{tabularx}

\subsection{POST /api/v1/nodes/\{nodeID\}/config-sync —— 下发配置}

用途：向边缘节点下发 ConfigMap/Secret 配置，供边缘应用使用。

请求体字段：

\begin{tabularx}{\textwidth}{l l l X}
  \toprule
  \textbf{字段} & \textbf{类型} & \textbf{必填} & \textbf{说明} \\
  \midrule

\subsection{八态响应语义}

三个下发端点统一使用以下响应语义（v0.7.0 起扩展为八态，新增 202/409/422/429）：

\begin{tabularx}{\textwidth}{l l X}
  \toprule
  \textbf{状态码} & \textbf{响应体（示例）} & \textbf{含义} \\
  \midrule
  200 & \texttt{\{"status":"ok","acked":true\}} & 边缘已确认（Ack ok） \\
  202 & release 对象（status=pending） & 已受理（异步执行，v0.7.0）：发布创建/回滚置位，结果以 release 对象回读为准 \\
  400 & \texttt{\{"error":"operation and pod.name are required"\}} & 请求非法：JSON 解析失败 / 缺必填字段 / operation 或 kind 不在白名单 / 资源格式非法或 request$>$limit \\
  404 & \texttt{\{"error":"node offline or not registered"\}} & 节点未注册或离线（消息未送达，无需重试） \\
  409 & \texttt{\{"error":"EDGEFLOW\_RESOURCE\_EXHAUSTED: ..."\}} & 冲突：podsync 资源超卖被拒（不落盘不建容器）；模型 API 冲突族（详见 \S\ref{sec:model-api-errors}） \\
  422 & \texttt{\{"error":"...", "unknownNodes":[...]\}} & 语义不可执行（v0.7.0）：发布目标版本非 active / 无 Ready 节点 / 白名单含未知节点 / 无 PrevActive \\
  429 & \texttt{\{"error":"ocsp rate limit exceeded"\}} & 限流：\texttt{/ocsp} per-IP 请求超限（默认 10 req/s、burst 20） \\
  500 & \texttt{\{"error":"send failed"\}} & 其他内部错误 \\
  502 & \texttt{\{"error":"edge rejected ack"\}} & 边缘明确拒绝：消息已送达但处理失败（重试无意义） \\
  504 & \texttt{\{"error":"ack timeout after retries"\}} & 确认超时且重试耗尽：可能已送达但未确认（可重试，边缘侧有幂等去重） \\
  \bottomrule
\end{tabularx}

语义区分（记忆要点）：\textbf{202} = 已受理异步执行，以 release 回读为准；\textbf{404} = 没送达（无需重试）；\textbf{409} = 送达但超卖/冲突拒绝（重试无意义）；\textbf{422} = 可执行性不满足（业务前置）；\textbf{429} = 限流（稍后重试）；\textbf{502} = 送达但被拒绝（重试无意义）；\textbf{504} = 可能送达但未确认（可重试）。

\section{OCSP 在线吊销查询（RFC 6960）}

\subsection{POST /ocsp}

用途：标准 OCSP（Online Certificate Status Protocol，RFC 6960）应答端点，供外部工具在线查询边缘节点证书的吊销状态。证书吊销后，除 mTLS 握手按 CRL（证书吊销列表）拒收外（见第 8 章证书管理），外部查询也可通过本端点进行。

\begin{lstlisting}
curl -X POST http://127.0.0.1:8080/ocsp \
  -H 'Content-Type: application/ocsp-request' \
  --data-binary @request.der
\end{lstlisting}

协议要点：

\begin{itemize}
  \item 请求体为 DER 编码的 OCSPRequest（\texttt{Content-Type: application/ocsp-request}），响应为 DER 编码的 OCSPResponse（\texttt{application/ocsp-response}），由云端 CA 私钥签名，响应自带可信性；
  \item 请求体上限 16 KiB（标准 CertID 请求远小于该值），超限返回 400；
  \item 免认证端点，以 per-IP 令牌桶限流防滥用：默认 10 req/s、burst 20，超限返回 429；速率可经环境变量 \texttt{EDGEFLOW\_CLOUDCORE\_OCSP\_RATE\_LIMIT} 调整；
  \item 成功响应带 \texttt{Cache-Control: max-age=3600}（响应 \texttt{nextUpdate} $\approx$ 7 天）；
  \item 吊销状态与 CRL 同源（均读 \texttt{crl.json}），证书被吊销后 CRL 与 OCSP 双通道同时生效；
  \item 状态码：200 返回签名后的吊销状态响应（\texttt{good}/\texttt{revoked}/\texttt{unknown}）；400 请求超限、为空或 DER 损坏；429 触发 per-IP 限流；500 CA 不可用、吊销记录损坏或响应构建失败（fail-closed，不静默放行）；
  \item 客户端查询库新增新鲜度校验入口 \texttt{OCSPStatusAtWithPolicy}/\texttt{ParseOCSPResponseWithFreshness}（fail-closed：过期或未来时间均拒绝，默认 5 分钟时钟 skew 容忍）；旧入口（\texttt{OCSPStatus}/\texttt{OCSPStatusAt}）行为不变；生产路径接入 OCSP 客户端时\textbf{须使用 WithPolicy 入口}（当前边缘 mTLS 握手仍按 CRL 校验）。
\end{itemize}

\section{模型 API（v0.7.0：模型仓库 / 版本管理 / 灰度发布）}
\label{sec:model-api}

v0.7.0 新增 17 个端点（总端点 14$\rightarrow$31，见 \S4.2）：模型 5 + 版本 6（CRUD 4 + activate/archive）+ 发布 5（创建/列表/详情/取消/回滚）+ 部署影子 1。全部注册于既有 apiMux，自动挂 \texttt{auth.Middleware}（Bearer Token，默认 off 向后兼容）与 \texttt{ledger.Middleware}（审计台账）——鉴权/审计零新代码；既有 14 端点一行不改。

核心概念：\textbf{“镜像即模型、Tag 即版本”}——平台不托管镜像实体，只登记镜像引用（mirror）+ sha256 摘要防篡改，镜像实体仍在客户镜像仓库；发布器复用既有 podsync（镜像 Pod）+ config-sync（模型版本/参数 ConfigMap）经可靠投递下发。\textbf{云边协议无新消息类型，边缘零代码改动}，旧版 edgecore 直接可用。

数据模型与状态机设计见 \texttt{docs/ARCHITECTURE.md} 决策 R16；实现包为 \texttt{cloud/pkg/modelrepo}（台账/校验/存储）+ \texttt{cloud/pkg/modelrelease}（灰度控制器/算法/部署执行器）。请求体上限 1 MiB（超限 400 \texttt{request body too large}）。

\subsection{对象模型与键空间}

五类对象：

\begin{tabularx}{\textwidth}{l l X}
  \toprule
  \textbf{对象} & \textbf{语义} & \textbf{关键字段} \\
  \midrule
  \texttt{Model} & 模型台账（一级对象，模型名唯一） & name（\verb|^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$|，禁 \texttt{/}）、description（$\leq$256）、type（$\leq$64，开放字符串）、metadata（键 $\leq$64 / 值 $\leq$1024）、createdAt/updatedAt（Unix 毫秒） \\
  \texttt{ModelVersion} & 版本台账（“Tag 即版本”） & version（字符集同 name，模型内唯一）、mirror（镜像 ref \textbf{必带 tag}）、sha256（\verb|^sha256:[0-9a-f]{64}$|，存储统一小写）、sizeBytes（$\geq$0）、archs（白名单 amd64/arm64，空 = 不限制）、status（draft/active/archived）、metadata（模型参数/阈值，发布时平铺进 config-sync） \\
  \texttt{ModelRelease} & 灰度发布任务（异步执行） & id（UUID）、model/version（目标版本，创建时须 active）、target（nodeIDs 白名单 $|$ percentage 1..100）、targetNodes（创建时物化的有序节点快照，运行期不重算）、batchSize（$\geq$1，默认 1）、pauseBetween（$\geq$0ms，默认 0）、failFast（默认 true）、prevActive（回滚目标；无则 \texttt{""}）、status（pending/running/succeeded/failed/canceled/rolled\_back）、nextBatchAt/createdAt/startedAt/finishedAt、rollbackRequested \\
  \texttt{NodeReleaseResult} & 逐节点执行结果（release 键下独立键） & nodeID、status（pending/deployed/failed/skipped）、version（该节点被部署到的版本）、reason（failed 原因）、batch（批次序号，1 起）、startedAt/finishedAt \\
  \texttt{DeploymentState} & 部署影子（跨发布全局视图） & model、version、mirror、releaseID、updatedAt \\
  \bottomrule
\end{tabularx}

\textbf{键空间}（新增前缀 \texttt{/edgeflow/models/}，与既有键完全隔离；\texttt{/edgeflow/\_meta/schemaVersion} 不 bump）：

\begin{itemize}
  \item \texttt{meta/<model>} —— 模型台账；
  \item \texttt{versions/<model>/<version>} —— 版本台账；
  \item \texttt{guards/<model>} —— 在途发布守卫（值 = releaseID）；
  \item \texttt{releases/<releaseID>} —— 发布 head（状态机 CAS 键）；
  \item \texttt{releases/<releaseID>/nodes/<nodeID>} —— 逐节点结果（perNode）；
  \item \texttt{releases/<releaseID>/lock} —— 发布领跑锁租约键（TTL 默认 60s）；
  \item \texttt{deployments/<model>/<nodeID>} —— 部署影子。
\end{itemize}

\textbf{版本状态机}（Activate/Archive API 驱动）：

\begin{lstlisting}
draft --activate--> active --archive--> archived
  |                     ^                    |
  +--delete-->(删)      | (激活时自动降级旧 active)  +--delete-->(删)
\end{lstlisting}

\begin{itemize}
  \item \texttt{activate}：仅 draft$\rightarrow$active；\textbf{自动把当前 active 版本置为 archived}（两键 CAS 序列 + 失败补偿）；archived 不可再激活；
  \item \texttt{archive}：仅 active$\rightarrow$archived；存在指向该版本的 pending/running 发布 $\rightarrow$ 409；
  \item \texttt{delete} 版本：仅 draft/archived（active $\rightarrow$ 409，先归档或删模型）；
  \item \textbf{发布/回滚不改变版本状态}：发布要求目标 active（只读校验）；回滚可部署 archived 的 prevActive（台账状态不变，由调用方按需显式 activate）。
\end{itemize}

\textbf{发布任务状态机}（控制器 + API 协作，head 键 CAS）：

\begin{lstlisting}
pending -> running -> 全部 deployed ---------------> succeeded
                     |- fail-fast 中止 / 存在失败(且跑完) -> failed
                     |- cancel（批次边界生效）-----------> canceled
                     +- rollback 置位 -> 逆序执行 ------> rolled_back

（成功/失败/取消均可再 rollback；终态后 guard 释放，同模型可再次发布）
\end{lstlisting}

\subsubsection{POST /api/v1/models/\{modelName\}/releases —— 创建灰度发布（202 异步受理）}

  -H 'Content-Type: application/json' \

请求体字段：

\begin{tabularx}{\textwidth}{l l l X}
  \toprule
  \textbf{字段} & \textbf{类型} & \textbf{必填} & \textbf{说明} \\
  \midrule
  \texttt{version} & string & 是 & 目标版本；\textbf{须为 active}（否则 422） \\
  \texttt{target.type} & string & 是 & \texttt{nodeIDs} / \texttt{percentage} 二选一 \\
  \texttt{target.nodeIDs} & []string & 条件必填 & 白名单；元素须匹配 \verb|^[A-Za-z0-9._-]+$| 且\textbf{全部已注册}（否则 422，响应 \texttt{"unknownNodes":[...]}）；允许离线节点入列（运行时按离线处理） \\
  \texttt{target.percentage} & int & 条件必填 & 1..100（越界 400）；分母 = 创建时刻 Ready 节点（0 台 Ready $\rightarrow$ 422） \\
  \texttt{batchSize} & int & 否 & $\geq$1，默认 1 \\
  \texttt{pauseBetween} & int64 & 否 & 批间暂停毫秒，$\geq$0，默认 0 \\
  \texttt{failFast} & bool & 否 & 默认 true \\
  \bottomrule
\end{tabularx}

创建前置校验（依序）：模型/版本存在（404）$\rightarrow$ 目标 active（422）$\rightarrow$ target 格式（400）$\rightarrow$ 白名单节点已注册 / percentage 合法（422/400）$\rightarrow$ 物化 TargetNodes $\rightarrow$ 确定 prevActive $\rightarrow$ guard CAS + release 键 CAS（同模型在途 $\rightarrow$ 409 含在途 releaseID；孤儿 guard 自愈）$\rightarrow$ perNode 全部 pending 预写。

响应 \textbf{202}：完整 ModelRelease 对象（status=pending，targetNodes 已物化，perNode 汇总 pending=N）。

\textbf{按比例分母口径与舍入}（创建时刻快照）：

\begin{tabularx}{\textwidth}{l l X}
  \toprule
  \textbf{readyCount} & \textbf{规则} & \textbf{例} \\
  \midrule
  0 & \textbf{422 拒绝创建}（\texttt{no ready nodes}） & — \\
  1 & n = 1（任何 pct 均落该节点） & 1 台 $\rightarrow$ 1 \\
  $\geq$2 & \textbf{n = ceil(readyCount $\times$ pct / 100)}，且 1 $\leq$ n $\leq$ readyCount & 23$\times$10\%$\rightarrow$3；3$\times$50\%$\rightarrow$2；100$\times$1\%$\rightarrow$1；10$\times$100\%$\rightarrow$10 \\
  \bottomrule
\end{tabularx}

\begin{itemize}
  \item \textbf{节点选择确定性}：Ready 名单按 NodeID 字典序取前 n（跨副本可复现）；archs 非空时先按 \texttt{node.arch $\in$ version.archs} 过滤再取前 n（过滤后 0 台 $\rightarrow$ 422，文案含 \texttt{no ready nodes for archs [...]}）；白名单模式不做 arch 过滤；
  \item \textbf{目标集合以创建时快照为准}：运行期节点掉线/新节点加入不重算；不同模式/迁移后的百分比目标集合不跨模式可比（\S\ref{sec:model-api-matrix}）。
\end{itemize}

\subsubsection{POST .../releases/\{releaseID\}/cancel —— 取消发布}

\begin{lstlisting}

\end{lstlisting}

响应 200 + release（status=canceled）；取消在\textbf{批次边界}生效，未执行节点 $\leq$1 扫描周期补齐 skipped（KNOWN-ISSUES L27）。终态 release cancel $\rightarrow$ 409（\texttt{\{"error":"release already <status>"\}}）。

\subsubsection{POST .../releases/\{releaseID\}/rollback —— 回滚发布（202 异步）}

\begin{lstlisting}
curl -X POST http://127.0.0.1:8080/api/v1/models/defect-detector/releases/<releaseID>/rollback
\end{lstlisting}

\begin{itemize}
  \item \textbf{前置校验}：status $\in$ \{running, succeeded, failed, canceled\}（pending/rolled\_back $\rightarrow$ 409）；\texttt{prevActive != ""} 且版本存在（否则 422 \texttt{no previous active version}）；\textbf{\texttt{release.version} == 模型当前 active 版本}（已被更新版本接管 $\rightarrow$ 409，文案引导显式 activate 目标旧版本或发起新发布，KNOWN-ISSUES L27）；
  \item 通过 $\rightarrow$ 202 + release（rollbackRequested=true）；控制器\textbf{逆序}逐批执行（批间 pause=0），失败不回滚中止（能回多少回多少，perNode 明细可查，KNOWN-ISSUES L24）；完成 $\rightarrow$ rolled\_back；
  \item \textbf{执行期复查}：runRollback 起始重读版本表——若执行前已被新版本接管或 prevActive 被删 $\rightarrow$ 中止：head=failed（reason 明确）+ 清除 rollbackRequested（防活锁）+ 未执行节点标 skipped；API 端 202 照旧，结果以 head 终态回读为准。
\end{itemize}

\subsubsection{GET /api/v1/models/\{modelName\}/deployments —— 部署影子查询}

\begin{lstlisting}
curl http://127.0.0.1:8080/api/v1/models/defect-detector/deployments
\end{lstlisting}

部署影子 = 云端期望态（对标设备 Desired），提供“版本—节点—时间”追踪（F41 台账）：每项 \texttt{\{"model":..., "version":..., "mirror":..., "releaseID":..., "updatedAt":...\}}，键为 \texttt{/edgeflow/models/deployments/<model>/<nodeID>}。写入时机：podsync + config-sync \textbf{均 acked 后}；写穿失败 $\rightarrow$ 日志 Warn（下发已生效，仅影子视图缺该记录，release/perNode 已持久化不受影响）。与边缘实际运行版本（PodStatus 上报）分离；重启后从 etcd 恢复（embed/外部），纯内存模式重启丢失（KNOWN-ISSUES L22）。影子为派生台账整值覆盖、无 CAS 需求——与 Desired（权威期望态，modRevision CAS）的差异为有意设计。模型删除 $\rightarrow$ 级联删除该模型部署影子。

\subsection{config-sync 载荷约定（边缘模型版本感知，零边缘代码）}
\label{sec:model-api-configsync}

发布器对每目标节点自动执行两步：① \texttt{podsync add}——Pod 名 \texttt{edgeflow-model-<sanitized>}（\texttt{sanitize(name)} = 小写 + \texttt{.}$\rightarrow$\texttt{-}）；namespace 固定 \texttt{edgeflow}；image = 版本镜像；\texttt{replicas=1}——模型实例多副本由用户后续自行 podsync 编排，发布语义 = “该版本上机”；② \texttt{config-sync add}——ConfigMap，同命名约定。两步均 acked $\rightarrow$ 部署影子写穿（\S\ref{sec:model-api-endpoints}）。

\textbf{ConfigMap 载荷约定}（\texttt{configs/edgeflow/edgeflow-model-<sanitized>}，保留键由发布器保证）：

\begin{lstlisting}
{
  "model":      "defect-detector",
  "version":    "v1.2.0",
  "mirror":     "registry.example.com/edgeflow/models/defect-detector:v1.2.0",
  "sha256":     "sha256:9f86...",
  "type":       "detection",
  "releasedAt": "1787000000000"
}
\end{lstlisting}

\begin{itemize}
  \item \textbf{保留键 6 个}：\texttt{model} / \texttt{version} / \texttt{mirror} / \texttt{sha256} / \texttt{type} / \texttt{releasedAt}；
  \item \texttt{version.metadata} 全部键值\textbf{平铺追加}进 data（模型参数随版本走）；与保留键冲突 $\rightarrow$ 保留键优先 + 控制器日志 Warn；
  \item 推理容器挂载/读取该 ConfigMap 即得“当前模型版本与参数”；版本切换 = 下一次 config-sync 覆盖（EdgeHub 幂等去重 + MetaManager SQLite 落盘保证重启后仍是新版本元数据）；
  \item 发布\textbf{回滚}同样经此通道把 version 字段改回 prevActive——边缘无状态机依赖，纯声明式收敛；
  \item 错误映射（perNode.Reason 文案）：\texttt{node offline or not registered} / \texttt{ack timeout after retries} / \texttt{edge rejected ack} / \texttt{send failed: <err>}。
\end{itemize}

\subsection{灰度运营建议}

\begin{enumerate}
  \item \textbf{节奏：先 1 台试点 $\rightarrow$ 小批 $\rightarrow$ 全量}。试点用白名单（\texttt{target.type=nodeIDs}，1 台）验证镜像可用与推理结果；小批用 \texttt{batchSize=1$\sim$2 + pauseBetween $\geq$30s} 留观察窗口；验证通过后放大比例或白名单；确认无误后 \texttt{percentage=100}；
  \item \textbf{fail-fast 保持默认开（true）}：单节点失败立即中止并标记剩余节点 skipped，避免坏版本扩散；需要“看完全部节点失败情况”时再显式关；
  \item \textbf{回滚前置条件 = “该发布版本仍是模型当前 active 版本”}（未被新版本接管）；已被接管 $\rightarrow$ 409，先显式 activate 目标旧版本（或发起新发布）再回滚。回滚为逆序批量执行、失败不回滚中止（能回多少回多少，perNode 明细可查）；
  \item \textbf{发布成功 $\neq$ 镜像可用}：平台下发的是声明（mirror ref），拉取发生在边缘；镜像仓库不可达/镜像损坏会在边缘 PodStatus 暴露（CrashLoop 等），发布任务本身仍可能 succeeded——发布前建议在试点节点确认 Pod Running；
  \item \textbf{耗时口径}：批内逐节点\textbf{串行}（每节点 2 次可靠下发，最坏 $\sim$10s+/节点超时）；batchSize 控制批粒度/暂停节奏，\textbf{不是并发度}；大 fleet 全量耗时 = $\Sigma$(单节点部署耗时) + $\Sigma$(pause)；
  \item \textbf{模型实例多副本}：发布语义 = “该版本上机”（replicas=1）；多副本由用户后续自行 podsync 编排。
\end{enumerate}

\section{排障指南}

\begin{tabularx}{\textwidth}{l X}
  \toprule
  \textbf{现象} & \textbf{处理} \\
  \midrule
  返回 401 & API 认证已开启但未携带或携带错误的 token；确认请求头 \texttt{Authorization: Bearer <token>} 正确 \\
  返回 400 & 请求体 JSON 非法或缺少必填字段、operation/kind 不在白名单；按响应中 \texttt{error} 提示修正 \\
  返回 404（下发类） & 节点未注册或离线，消息未送达；先确认 edgecore 运行状态与节点 ID 拼写，无需重复重试 \\
  返回 502 & 消息已送达但被边缘拒绝；检查请求体是否符合边缘校验规则（如设备名、属性名是否正确、namespace 是否匹配已注册 Mapper） \\
  返回 504 & 可能已送达但未确认（超时重试耗尽）；可稍后重试，边缘侧有幂等去重，不会重复执行 \\
  返回 409 & 两类场景：podsync 超卖拒绝（响应 error 为 \texttt{EDGEFLOW\_RESOURCE\_EXHAUSTED}，不落盘不建容器，重试无意义）；模型 API 冲突族（模型/版本已存在、删除 active 版本、状态机非法、同模型在途发布、CAS 冲突耗尽、回滚被新版本接管）——按响应 \texttt{error} 文案与上下文字段定位（发布冲突 409 带 \texttt{releaseID}） \\
  返回 422 & 模型发布业务前置不满足：目标版本非 active、无 Ready 节点、白名单含未知节点（响应带 \texttt{unknownNodes}）、无 PrevActive 可回滚——按提示修正后重新创建发布 \\
  发布创建/回滚返回 202 & 异步任务：用 \texttt{GET /api/v1/models/\{modelName\}/releases/\{releaseID\}} 回读状态与 perNode 汇总（pending$\rightarrow$running$\rightarrow$终态），不要以 202 视为执行完成 \\
  日志出现 \texttt{concurrent-write} & 外部多副本形态下多副本并发写同一设备 Desired，CAS 冲突重试耗尽属预期语义（HTTP 仍 200）；重发指令即可收敛 \\
  云端重启后查询为空 & v0.4.0 起分级持久化：注册台账与设备 Desired 跨重启保留（节点重启后短暂 Unknown，边缘 $\leq$1 心跳周期翻新 Ready，无需重新注册）；Pod 状态与上报属性短暂清空（$\leq$1 上报周期自愈），非永久丢失 \\
  \bottomrule
\end{tabularx}
