\chapter{升级与回滚}
\label{ch:7}

EdgeFlow 的升级/回滚由安装管理 CLI \textbf{keadm} 提供，作用在
\textbf{keadm 生成的产物文件}层面（\texttt{edgecore.env} /
\texttt{edgecore.service} / \texttt{install.sh}），配合\textbf{操作台账}
（ops-ledger）实现可审计、可恢复的升级流程。部署在 Kubernetes 上的云端
组件则走 Helm 路径。两条路径互不替代，本章分别说明；此外，云端从
v0.4.0 起具备独立的分级持久化与多副本升级语义（见第~\ref{sec:7-cloud}~节）。

\section{机制总览}

\begin{table}[htbp]
\centering
\caption{升级回滚机制一览}
\label{tab:7-overview}
\begin{tabularx}{\textwidth}{l X}
\toprule
\textbf{能力} & \textbf{说明} \\
\midrule
备份模型 & 升级前把产物快照备份到 \texttt{backups/<id>/}（含
\texttt{manifest.json} 与每文件 \texttt{sha256}） \\
台账模型 & 每次操作（含失败）追加写 \texttt{ops-ledger.jsonl}，逐行 JSON \\
版本标记 & \texttt{edgecore.env} 内版本标记行，join 写入、upgrade 更新、rollback 恢复 \\
数据隔离 & 不触碰数据目录（SQLite 等）与用户文件 \\
\bottomrule
\end{tabularx}
\end{table}

\textbf{边界}：本机制只保证离线产物可恢复；镜像 tag 变更、edgecore
二进制替换、节点侧 \texttt{install.sh} 的实际执行不在产物级机制内，需
结合发布流程执行。

\section{升级前准备}

\begin{enumerate}
  \item 记录当前产物基线（可选但推荐）：
\begin{lstlisting}
sha256sum $OUT/edgecore.env $OUT/edgecore.service $OUT/install.sh > baseline.sha
\end{lstlisting}
  \item 如需在台账中记录操作人，设置环境变量：
\begin{lstlisting}
export KEADM_OPERATOR=alice
\end{lstlisting}
        未设置时台账记录 \texttt{unknown}。
\end{enumerate}

\section{升级：keadm upgrade}

\begin{lstlisting}
# 升级到 v0.7.0（先备份 → 更新版本标记 → 写台账）
keadm upgrade --version=v0.7.0 --output-dir=./keadm-out

# 演练模式：备份后模拟失败（产物不会被修改），用于演练回滚流程
keadm upgrade --version=v0.7.0 --simulate-failure --output-dir=./keadm-out
\end{lstlisting}

执行流程：

\begin{enumerate}
  \item \textbf{校验版本格式}：必须为 \texttt{vX.Y.Z}（如 \texttt{v0.7.0}），
        非法或与当前版本相同 → 退出码 2，不产生备份；
  \item \textbf{预检}：三个产物文件（env/service/install.sh）任一缺失 →
        退出码 1；
  \item \textbf{备份}：复制产物到 \texttt{backups/<id>/}（\texttt{<id>}
        为到秒的时间戳，同秒追加 \texttt{-2}、\texttt{-3}\ldots），写入
        \texttt{manifest.json}（时间/版本/操作人/文件清单/sha256）；
  \item \textbf{更新版本标记}：整行替换 \texttt{edgecore.env} 中的版本标记；
  \item \textbf{写台账}：追加 \texttt{result=ok} 记录。
\end{enumerate}

任一环节失败：退出码 1，台账记 \texttt{failed}，并提示
「执行 \texttt{keadm rollback --latest} 可恢复」。备份目录只增不删，
保留恢复路径与审计现场。

\section{回滚：keadm rollback}

\begin{lstlisting}
# 取最新有效备份回滚
keadm rollback --latest --output-dir=./keadm-out

# 指定备份 id 回滚（id 见 backups/ 目录名或台账）
keadm rollback --backup=20260814-190701 --output-dir=./keadm-out
\end{lstlisting}

执行流程：

\begin{enumerate}
  \item \textbf{参数校验}：\texttt{--backup} 与 \texttt{--latest} \textbf{互斥}，
        必须二选一，违规退出码 2；
  \item \textbf{定位备份}：\texttt{--latest} 取时间戳最新（含序号后缀）；
        \texttt{--backup=<id>} 精确匹配，不存在 → 退出码 1；
  \item \textbf{完整性校验}：\texttt{manifest.json} 可解析、字段完整、
        清单内文件存在且 \texttt{sha256} 一致；校验失败 → 报错并
        \textbf{保留备份目录}；
  \item \textbf{恢复}：逐文件复制回输出目录，回读校验内容一致，并
        强制恢复权限（env \texttt{0600} / service \texttt{0644} /
        install.sh \texttt{0755}）；
  \item \textbf{写台账}：追加 \texttt{result=ok}（\texttt{from}=当前版本，
        \texttt{to}=备份版本）。
\end{enumerate}

\textbf{失败兜底}：任何自动恢复不可用的场景，备份目录保留完整快照，
错误提示中给出逐文件人工恢复命令，例如：

\begin{lstlisting}
cp backups/<id>/edgecore.env    <output-dir>/edgecore.env
cp backups/<id>/edgecore.service <output-dir>/edgecore.service
cp backups/<id>/install.sh      <output-dir>/install.sh
\end{lstlisting}

\section{台账查询：keadm ops-ledger}

\begin{lstlisting}
# 最近 20 条（默认）
keadm ops-ledger --output-dir=./keadm-out
# 最近 N 条
keadm ops-ledger --limit=5 --output-dir=./keadm-out
\end{lstlisting}

输出为 JSON 数组，逐行 JSON 原样保留，机器可解析。记录字段：
\texttt{ts}（RFC3339 时间）、\texttt{action}（\texttt{upgrade}/\texttt{rollback}）、
\texttt{from}/\texttt{to}（版本）、\texttt{result}（\texttt{ok}/\texttt{failed}）、
\texttt{operator}（操作人）、\texttt{note}（备份 id、失败原因等）。
台账不存在时输出 \texttt{[]} 并以 0 退出；损坏行跳过并附警告。

\section{Helm 路径（云端组件）}

云端 cloudcore 若通过 Helm Chart（\texttt{build/charts/edgeflow}）部署，
升级与回滚走标准 Helm 流程：

\begin{lstlisting}
# 升级（--install 兼容首次安装）
helm upgrade --install edgeflow build/charts/edgeflow \
  --set cloudcore.env.EDGEFLOW_CLOUDCORE_TLS=on \
  --set cloudcore.env.EDGEFLOW_CLOUDCORE_CERT_DIR=/data/certs

# 回滚到上一个版本
helm rollback edgeflow <rev>
\end{lstlisting}

\textbf{版本标记约定}：\texttt{keadm join} 生成的 \texttt{edgecore.env}
首行注释下含版本标记行，与 \texttt{keadm init} 默认镜像 tag
（\texttt{edgeflow/cloudcore:v0.7.0}）对齐：

\begin{lstlisting}
# keadm 产物版本: v0.7.0
\end{lstlisting}

旧版 join 产物无此标记时，\texttt{upgrade} 视当前版本为 \texttt{unknown}，
更新时自动追加标记行（兼容升级路径）。\texttt{rollback} 恢复后标记行
随文件内容一并还原。

\section{云端（cloudcore）升级与回滚（v0.4.0 起语义）}
\label{sec:7-cloud}

v0.4.0 起，云端引入\textbf{分级持久化}（嵌入式 etcd），v0.5.0 起支持\textbf{外部
etcd 模式}，v0.6.0 起支持\textbf{真多活多副本}，v0.7.0 新增\textbf{模型仓库
键空间}——云端升级/回滚因此具备独立语义。本节按版本逐项说明；完整迁移
runbook 见部署文档 \texttt{DEPLOYMENT.md}（§10.7/§10.8/§10.9）。

\subsection{v0.4.0：嵌入式 etcd 持久化升级}

\begin{itemize}
  \item \textbf{自动建库，无迁移脚本}：\texttt{EDGEFLOW\_CLOUDCORE\_ETCD\_ENABLED}
        默认 \texttt{true}，升级后首次启动自动创建嵌入式 etcd 库并从前置
        Range 全量 Load 既有数据；旧节点在保留期内（\texttt{NODE\_RETENTION}，
        默认 24h）重新注册后立即可见，无需重新注册；
  \item \textbf{Helm 升级必须确保 PVC}：Chart 默认挂载 1Gi PVC 到
        \texttt{/data}；若以 \texttt{emptyDir} 运行，持久化\textbf{名存实亡}，
        容器重启即清空；
  \item \textbf{embed 模式 replicaCount 必须为 1}：多副本各自内嵌 etcd 会形成
        脑裂，Chart 在渲染期以 \texttt{\{\{ fail \}\}} 守卫拒绝
        \texttt{replicaCount>1}；
  \item 监控告警阈值需容忍「Pod/上报数据重启后短暂清空（不超过 1 个上报周期
        自愈）」窗口；cloudcore 资源占用上升（RSS 约 31--34MB），Helm 资源
        建议 requests 256Mi / limits 1Gi。
\end{itemize}

\subsection{备份与恢复 runbook（简化版）}

\textbf{在线快照}（推荐；嵌入式 etcd 运行中执行）：

\begin{lstlisting}
etcdutl snapshot save --endpoints=http://127.0.0.1:12379 snapshot.db
\end{lstlisting}

\textbf{离线拷贝}（需先停止 cloudcore 进程，保证数据目录一致）：

\begin{lstlisting}
# 停进程后执行
cp -a data/etcd data/etcd.bak
\end{lstlisting}

\textbf{恢复}（将恢复出的数据目录替换到 \texttt{ETCD\_DATA\_DIR} 后启动
cloudcore）：

\begin{lstlisting}
etcdutl snapshot restore snapshot.db --data-dir=<全新目录>
\end{lstlisting}

\textbf{注意}：\textbf{文件拷贝 $\neq$ 有效备份}——运行中直接复制数据目录会得到
不一致状态，必须走 \texttt{etcdutl snapshot}（在线）或停进程后
\texttt{cp -a}（离线）。外部 etcd 模式的备份恢复由外部集群侧负责（同为
etcdutl 流程，endpoints 指向外部集群）。

\subsection{v0.5.0：外部 etcd 模式切换}

设置 \texttt{EDGEFLOW\_CLOUDCORE\_ETCD\_ENDPOINTS}（非空）即切换为\textbf{外部
直连共享 etcd 集群}模式（跳过 embed，不建目录不占端口；embed 相关变量
设置仅告警忽略）。切换方式二选一：

\begin{itemize}
  \item \textbf{快照恢复迁移}：外部集群先 \texttt{etcdutl snapshot restore}
        导入既有数据，再切换 endpoints；
  \item \textbf{零迁移自愈}：不迁移历史数据，节点重新注册后台账与 Desired
        重建，上报数据不超过 1 个周期自愈（适用于可接受重建的场景）。
\end{itemize}

\textbf{外部集群建议配置}：3 节点奇数/同地域；quota 256MiB；auto-compaction
1h；etcd 侧最小权限角色（readwrite \texttt{/edgeflow/}）。明文护栏与
TLS/mTLS 配置见第~\ref{ch:8}~章。

\subsection{v0.6.0：外部模式多副本（真多活）}

v0.6.0 起外部模式支持 \texttt{replicaCount>1} active-active 多副本。扩容
前置条件（三项齐备）：

\begin{itemize}
  \item \textbf{同版本}：所有副本必须同一 cloudcore 版本（混合版本未验证，
        且 v0.5.0×v0.6.0 混跑会被旧版 GC 误删活节点）；
  \item \textbf{3 节点 quorum}：外部 etcd 集群至少 3 节点，容忍单点故障；
  \item \textbf{共享 endpoints}：所有副本指向同一外部 etcd 集群。
\end{itemize}

扩容：

\begin{lstlisting}
kubectl scale deployment edgeflow-cloudcore --replicas=2
\end{lstlisting}

多副本形态下判活由 etcd \textbf{租约}承担（\texttt{NODE\_LEASE\_TTL}，默认
300s），NodeController 停用；\texttt{MULTI\_REPLICA} 由 Chart 自动注入，
\texttt{/healthz} 反映 etcd 连接状态（失联超过 TTL 返回 503，K8s liveness
重启自愈）。

\textbf{升级/回滚纪律}：无论升级还是回滚，一律\textbf{全停再全起}——先
\texttt{kubectl scale --replicas=0}，确认全部副本退出后，再以新版本
\texttt{scale --replicas=1}（或期望副本数）拉起。\textbf{禁止混合版本
多副本混跑}（v0.5.0×v0.6.0 同连一集群会误删活节点；v0.6.0×v0.7.0 未验证，
建议同版本全量切换）。回滚到 v0.5.0 后可选用 \texttt{etcdctl del
/edgeflow/registry/heartbeats --prefix} 清理残留心跳键（可选，v0.5.0
不读写该前缀）。

\subsection{v0.7.0：模型仓库升级（零迁移）}

v0.7.0 新增 \texttt{/edgeflow/models/} 键空间（模型/版本/发布/部署影子），
与既有键空间完全隔离，\textbf{升级零迁移}：边缘节点零动作，旧版 edgecore
直接可用；schemaVersion 不 bump。

回滚到 v0.6.0 后，\texttt{/edgeflow/models/} 残留键无害（v0.6.0 不读写该
前缀）；如需彻底清理（可选）：

\begin{lstlisting}
etcdctl del /edgeflow/models --prefix
\end{lstlisting}

\section{端到端演练建议}

\begin{lstlisting}
keadm init  --output-dir=$OUT
keadm join  --cloudcore-ip=192.168.1.10 --token=abc123 \
            --node-id=edge-worker-01 --output-dir=$OUT
keadm upgrade --version=v0.7.0 --simulate-failure --output-dir=$OUT   # 预期失败 exit=1
keadm rollback --latest --output-dir=$OUT                             # 恢复
keadm upgrade --version=v0.7.0 --output-dir=$OUT                      # 真实升级
keadm rollback --latest --output-dir=$OUT                             # 真实回滚
sha256sum -c baseline.sha                                             # 产物一致
keadm ops-ledger --output-dir=$OUT                                    # 台账 4 条
\end{lstlisting}

注意：重复升级每次都会产生新备份（只增不删），长期使用请定期人工归档
\texttt{backups/} 目录。

云端（cloudcore）侧的升级演练与 runbook 见部署文档
\texttt{DEPLOYMENT.md} §10.7.5（外部模式迁移）、§10.8.5（多副本扩容）与
§10.9.4（模型仓库升级）；云端走 Helm 路径升级/回滚时，同样遵循
第~\ref{sec:7-cloud}~节的全停再全起纪律。
