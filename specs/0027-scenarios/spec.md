# spec 0027 — 三场景端到端验收（v0.54.0，G29）

> 版本：v0.54.0 ｜ 缺口：G29「三场景端到端联调」｜ 上游：spec 0024/0025/0026
> replan 验收锚：三场景 e2e 全绿 + 联调记录

## 背景与范围裁决

replan 规划「三场景端到端验收 + 平台对接」。v0.53 已交付转发出口；本版以三条
**场景级 e2e**把 v0.37–v0.53 的能力串联成业务闭环，并交付验收文档。
**本版零 API 变更（契约 128 不变）**——纯验收层，发现问题以修复提交留痕。

**裁决：三场景 = 告警通知闭环 / 维护预警闭环 / 优化设定值闭环；全部走真实
cloudcore+edgecore 进程与 RBAC 环境（非单测替身）。**

## 裁决

1. **场景 A 告警通知闭环**：阈值规则触发真告警（critical）→ 告警中心 → 区域汇聚
   （hierarchy summary alarmActiveCount 可见）→ 转发出口 webhook 送达（通知系统
   等价物，HMAC 签名校验）。视频源等价声明：视频告警与设备告警在平台内同为
   Alarm 事件，视频接入链路已有独立 e2e（v0.42–v0.44），本场景聚焦「告警产生后」
   的平台链路。
2. **场景 B 维护预警闭环**：预警阈值（warning）→ ack → assign（维护班 + ticketRef
   工单语义）→ close；区域×状态告警矩阵（hierarchy alarms）三态迁移可见。
3. **场景 C 优化设定值闭环**：设定值建单（requireApproval）→ approve → 边缘执行 →
   SetpointResult 回告 applied；拒绝路径 → rejected 留痕。
4. **零契约变更**：端点 128 不变、消息 19 不变；既有能力只消费不扩展。
5. **验收文档**：docs/SCENARIO-E2E.md——三场景输入/链路/断言/通过判据 + 验收记录
   （如实登记，含等价物声明）。
6. **非目标**：真视频源接入（用告警事件等价）、外部工单系统真实集成、通知渠道
   多样化（短信/邮件）、性能口径（场景级只验功能闭环）。
